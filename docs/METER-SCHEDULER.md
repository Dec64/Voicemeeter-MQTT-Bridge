# Independent meter scheduling

`MeterTelemetryLoop` joins the corrected source sampler, two peak accumulators and two capacity-one queues. It is not instantiated by `BridgeService`; no live v2 publishing starts with this change. Tests use fake levels and a fake clock driving the real .NET `PeriodicTimer`.

One `RunAsync` call owns one session. It captures settings before the first await, starts windows at run time, then samples enabled registry sources and their configured taps once per timer tick. Each source/tap result feeds both enabled accumulators, without repeating native reads for each stream. The first sample is taken after one sample interval. Global v2 disable, both streams disabled, or no enabled source ends the run without level reads or a timer. Disabled-stream queues are completed.

Fast and slow deadlines are independently anchored to monotonic session time. At a due tick each stream completes at most one window and nonblockingly replaces its pending snapshot. A late tick produces an actual elapsed window; it never invents missed samples or replays a burst of past windows. Cadences not divisible by the sample interval are quantized to sampling ticks without accumulating drift. For example, 50 ms sampling with a 75 ms publishing target completes at ticks 100, 150, 250, 300 ms under ideal timing. Configured window length remains the existing wire value; actual duration and capture age remain in the snapshot.

Consumers use `ReadFreshAsync` with a cadence-appropriate budget and recheck freshness before transport submission. A delayed window may already be stale when produced. There is no networking, serialization or awaited delivery in the sampling loop, so unread queues cannot back up the loop. Actual native read duration can still delay sampling; this does not prove responsiveness or a 20 Hz delivery rate.

An expected level-read failure invalidates its own source window through the existing sampler/accumulator. Unexpected exceptions fault the run task and complete both queues. The caller must observe that task. Cancellation is checked before and after each synchronous source/tap sample; an in-flight sample cannot be aborted safely. Cancellation ends normally, disposes the timer and completes both queues without flushing a partial window. Completion preserves already-pending snapshots for normal drain/age checks. Repeated or concurrent starts are rejected without closing an already-running session.

The session owns queue writes/completion; its single consumer per queue owns reads. Do not mutate settings concurrently with startup. Runtime configuration or reconnect transitions must cancel and await the old run, abandon old queues, and build a new registry/session. Native integration must supply the Remote owner-backed level interface: async continuations are not a fixed DLL thread. No matching SDK requirement has been waived and no new native binding is added.
